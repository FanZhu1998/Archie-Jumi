# Archie & Jumi — Phase 3 prompts for optional sheets E–H

Prepared on October 18, 2026 for app 1.2.0. **None of these sheets exists yet.** They extend the eight A–D sheets recorded in `realistic-art-prompts.md` with in-between poses (E–G) and true left-facing poses (H). Every sheet is optional and independent: `npm run art` uses a sheet only when its file is present, separately for each kitten, and packs exactly as before when none is. Clip timings, budgets and the true-left rules are in `art-direction.md`.

## Rules for every prompt

- Use the same built-in imagegen workflow as the A–D record. Attach, in this order: input 1, the kitten's realistic master portrait (`public/pets/{archie,jumi}/portrait.png`); input 2, the real photograph (kept outside the repository and the app); then the existing sheets each prompt names (`artwork/realistic/{archie,jumi}-{a,b,c,d}.png`), so scale, camera and lighting match. If the tool accepts fewer references, keep inputs 1 and 2 and the first sheet named.
- One square 2×2 sheet per prompt, poses in reading order, every kitten fully inside its own cell with wide transparent gutters. The prompts reuse the sheet A layout wording, which produced sheets that needed no crop corrections.
- Sheets E, F and G face RIGHT like A–D. Sheet H faces LEFT and shows the kitten's real left side: never flip existing art to make it.
- Each new pose is the moment between existing poses (or the same pose a moment later), at the same body size and camera distance. It is not a new composition.
- Reject a result with identity drift (face shape, eye colour, Archie's blaze, Jumi's stripes, age), a changed body size, cropped ears, paws, tail or whiskers, a fake checkerboard, a floor, shadow, prop or text.
- Save each accepted sheet as a lowercase RGBA PNG named `{archie,jumi}-{e,f,g,h}.png` in `artwork/realistic/`, or in a staging folder first (see Review).

Use case: identity-preserve. Asset type: photorealistic transparent desktop pet sprite sheet with in-between poses for an existing set. Preserve the exact kitten identity and baby proportions from the provided portrait (input 1) and real photo (input 2). Inputs 3, 4 and 5 are his existing sheets A, B and C: match their animal scale, camera height, three-quarter angle, fur and soft daylight exactly, so each new pose plays between the existing ones without a jump.
CRITICAL LAYOUT: a square image with exactly FOUR separate kittens in a strict 2 columns by 2 rows arrangement. Row-major poses: top left the walking passing pose between the two walking steps of sheet A, left forepaw planted under the chest carrying his weight while the right forepaw is lifted and swinging forward, hind legs passing each other; top right the opposite passing pose, right forepaw planted under the chest while the left forepaw is lifted and swinging forward; bottom left exactly the curled sleeping pose of sheet B (top right), eyes closed and tail tucked, same outline and position, with chest and flank very slightly expanded in a slow breath in; bottom right exactly the eating pose of sheet C (bottom right), nose lowered to the ground, jaw slightly open mid-chew and head lifted a few degrees, no food or object shown. Preserve body size across all cells and match inputs 3 to 5.
ARCHIE: gray-and-white tabby, white blaze, white chest/paws and muzzle, pink nose, gray kitten eyes.

## Review steps

1. **Stage the new sheets.** Either save them in `artwork/realistic/`, or keep them in a staging folder together with copies of all eight A–D sheets (packing always needs A–D), for example `work/new-art/` (`work/` is git-ignored). Unchanged copies of the bundled sheets keep the rectangles in `artwork/realistic/crops.json`, so a staging `crops.json` is needed only for rectangles of new or changed sheets.
2. **Check without writing.** Run `npm run art -- --check` (add `--source-dir=work/new-art` for a staging folder). It validates every sheet and prints, per kitten, the optional sheets found, each clip they change, the common scale, the atlas and page sizes and every warning. Nothing is written. Typical findings:
   - *opaque pixels touch a crop edge*: a pose crosses its cell or the image edge. Regenerate it, or add a `crops.json` rectangle that follows the transparent gap, keyed by file and pose name, for example `"archie-f.png": { "pounce_air": { "left": 600, "top": 0, "width": 654, "height": 640 } }` for the top-right pose of a 1254-pixel sheet. Rectangles never resize or repaint art. A misspelled sheet or pose name stops packing.
   - *fine/low-alpha pixels touch a crop edge*: faint fur or whiskers reach the cell border. Inspect them in the clip preview.
   - *Optional pose … lowers the common scale*: the new pose is wider or taller than any A–D pose, so every frame of that kitten would shrink. Regenerate it at the A–D camera distance.
   - *the whole left-facing clip stays mirrored because sleep_b has no true-left pose*: expected when E and H are both present. The left-facing sleep clip remains mirrored, and `sleep_left` is used only without sheet E.
   - *not a sheet name* or *rename to …*: the file name is not one of the sixteen sheet names, or not lowercase.
3. **Pack into a staging folder and look.** Run `npm run art -- --output-dir=work/staging/pets --work-dir=work/staging` (plus `--source-dir=` if staged). Review in `work/staging/`:
   - `realistic-clip-preview.png` and `realistic-clip-preview-dark.png`: every frame of every clip in playing order, right-facing then left-facing, labelled `mirror` or `true left`, with durations and a line at the ground anchor. Check that the face, markings and age match in every frame; that body size and paw contact sit on the ground line; that each in-between reads as the moment between its neighbours (walk and trot A → C → B → D, pounce crouch → crouch deeper → air → land); that true-left frames show the markings on the correct side; and that there is no light or dark halo on either background.
   - `realistic-animation-preview.png` and `realistic-animation-preview-dark.png`: the contact sheets with the first pose of each action for both kittens, for likeness and consistent scale.
   - `realistic-pair-preview.png`: muzzle contact of the nose-touch poses at engine spacing (unchanged by E–H).
   - `realistic-packing-report.json`: `commonScale` next to `scaleFromSheetsAtoD`, every clip with its poses, durations and left-facing art, crops and warnings.
4. **Pack for the app.** When the staging review passes, put the accepted sheets in `artwork/realistic/` and run `npm run art`, then `npm test` and `npm run smoke`. Watch the kittens in the app (`npm start`) on light, dark and patterned backgrounds, walking and trotting both ways, napping, eating, grooming, being petted and pouncing, at 96, 128 and 192 DIP.
5. **Keep only accepted sheets.** Move every sheet you reject out of `artwork/realistic/`, for example to `work/rejected/` (git-ignored). Do not rename it inside `artwork/realistic/`: that folder is tracked, so a renamed sheet gets committed with the next change, and every later packing run reports it as *not a sheet name*. Packing then falls back to the A–D clips for that kitten. Never commit rejected or synthetic stand-in sheets.
6. **Update the records.** Add the prompts actually used to this file or to `realistic-art-prompts.md`. After the final `npm run art`, copy `work/realistic-packing-report.json` to `docs/realistic-packing-report.json`. Then correct every statement that the new art makes false:
   - `docs/VALIDATION.md`: the *Realistic asset packing* row (source poses, directional sprite frames and action pages) and the art-limits line (mirrored left-facing poses, single-pose actions).
   - `README.md`: the artwork paragraph (source poses, which actions use several poses, mirrored left-facing sprites).
   - `docs/release-notes.md`: the new sheets, the clips they change and any remaining art limits.
